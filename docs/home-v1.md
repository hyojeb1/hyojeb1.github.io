# 개인 홈 V1 · 현재 구현 기록

2026-10-19. 현재 홈의 구조와 구현 결정을 기록한다. 기존 `AGENTS.md`,
`DESIGN.md`, `README.md`에 남은 포트폴리오 중심의 화면 구성과 시각적 금지 목록은
당시의 기록이다. 새 홈에는 이번 요청과 이 문서의 구현을 적용한다.
여행·체스 데이터의 출처와 공개 범위는 기존 구현을 보존한다.

## 경험과 주소

- `/`: 개인 소개, 나이트가 탐험하는 8×8 마을, 일반 내비게이션, 이메일·GitHub.
- `/portfolio/`: 이전 메인의 자기소개와 여섯 작업물. 상대 경로와 홈 링크만 변경했다.
- `/works/`: 프로젝트 상세 주소를 보존한다. works 복귀 링크는 `/portfolio/#works`로 연결한다.
- `/travel/`, `/chess/`: 기존 페이지와 데이터 생성 코드를 보존한다.
- 예전 `/#works`, `/#about`, `/#contact` 북마크는 해당 포트폴리오 앵커로 이동한다.
- `/lab/`은 만들지 않았다. 마을의 수정 소품은 향후 실험을 위한 장식이며 링크가 없다.

처음에는 b1의 백 나이트를 조작한다. +가 표시된 칸으로 L자 점프한다.
건물이나 장소 선택 버튼을 누르면 설명과 자동 이동·페이지 바로 열기를 제공한다.
방문자는 나이트를 움직이지 않아도 일반 링크로 모든 콘텐츠에 접근할 수 있다.

## 기술을 선택한 이유

설치 의존성 없는 HTML·CSS·ES Module과 Canvas 2D를 사용한다.
사선 투영, 높이가 있는 건물, 겹침 순서, 그림자로 2.5D 장면을 만든다.
기물·건물·소품은 코드로 직접 그렸고 외부 그래픽 에셋은 가져오지 않았다.
기존 자체 호스팅 폰트를 재사용한다. WebGL·실제 3D 카메라는 V1에 도입하지 않았다.

평면 지도는 같은 월드 데이터를 읽는 HTML 버튼 격자다. Canvas 픽셀에 접근성 정보를
억지로 대응시키는 대신, 지도와 별도 이동 버튼을 키보드 조작 경로로 제공한다.
장소 패널과 지도는 네이티브 dialog의 top layer를 사용한다. 모바일 패널은 하단 시트다.

## 파일과 의존 관계

```
index.html              개인 홈의 의미 구조·일반 링크·dialog
home/home.css           홈 전용 스타일. 기존 style.css와 분리
home/world.js           크기·시작 위치·목적지·소품·길 데이터와 검증
home/rules.js           순수 나이트 규칙, 착지 판정, BFS 최단 경로
home/movement.js        점프 상태·경로 큐·취소·보간. DOM에 의존하지 않음
home/camera.js          사선 투영·역투영, 카메라 위치·줌·추적
home/renderer.js        Canvas 도형과 깊이 정렬·화면 범위 선별·건물 히트 영역
home/input.js           Pointer Events: 탭·드래그·핀치·휠
home/app.js             위 모듈과 HTML UI를 연결, 상태 알림과 프레임 예약
portfolio/index.html    보존한 포트폴리오
scripts/build-site.py   공개 경로 allowlist 패키징
scripts/check_site.py   실제 패키징 결과의 링크·리소스·공개 범위 검사
scripts/test_home.mjs   규칙·BFS·이동 상태·카메라 자동 테스트
scripts/check_home_browser.mjs  로컬 Chrome의 화면·실제 브라우저 입력 이벤트 검사
```

데이터 → 규칙·경로 → 이동 상태 → 카메라·렌더링 순으로 흐른다.
입력은 app에 의도를 전달하고, app만 이동과 UI를 갱신한다.

## 좌표와 확장

- 체스 좌표: x=0은 a 파일, y=0은 1 랭크. 시작 위치는 데이터에서 변경한다.
- 투영 좌표: `project()`가 타일 단위를 사선 평면의 픽셀 단위로 바꾼다.
- 화면 좌표: 카메라 이동·줌과 Canvas 중심을 적용한 CSS 픽셀이다.
- 렌더 버퍼: 화면과 별도로 DPR을 적용하며 최대 2로 제한한다.

월드 크기는 world 데이터에 한 번 정의한다. 경계, BFS, 투영, 지도는 이 값을 읽는다.
새 목적지는 destinations에 id·좌표·kind·제목·설명·URL을 추가한다.
새 종류의 외형을 원할 때 renderer에 해당 그리기 함수를 추가한다.
소품의 `blocksLanding`은 착지만 막는다. 목적지 칸은 들어갈 수 있는 광장으로 취급한다.
길은 장식이며 나이트의 이동 규칙을 바꾸지 않는다.

16×16·32×32·직사각형 월드는 알고리즘 테스트만 실행한다. 실제로 생성하는 것은 8×8뿐이다.
타일은 화면 역투영으로 산출한 범위만 그리며, 소품은 화면 밖 그리기를 생략한다.
더 큰 월드에서 오브젝트가 많아지면 현재 그리기 경계 앞에 공간 인덱스를 붙일 수 있다.

## 입력과 상태 처리

- 마우스/터치 탭: + 칸으로 이동, 건물은 설명 패널.
- 한 손가락/마우스 드래그: 카메라 이동. 탭 임계값은 터치 10px, 마우스 6px.
- 두 손가락 핀치/휠/확대·축소 버튼: 줌. 손가락 중간 지점을 기준으로 확대한다.
- 내 위치 버튼: 현재 줌을 유지하면서 나이트 추적을 다시 켠다.
- 평면 지도: 좌표·기물·장소·선택 장소·착지 불가 칸·합법 수를 표시한다.
- 지도에서 방향키/Home/End로 칸 탐색, Enter/Space로 선택한다.
- Esc 또는 닫기 버튼: dialog 닫기. dialog는 포커스를 관리한다.
- 자동 이동 중 이동 입력과 다른 경로 시작은 차단한다. 장소 미리보기는 가능하다.
- 이동 중단/Esc: 남은 경로를 비우고 진행 중인 점프는 합법적인 칸에 착지한다.
- 페이지 이동은 항상 명시적인 링크 선택으로만 일어난다. 도착만으로 이동하지 않는다.

점프는 smoothstep 수평 보간과 사인 수직 궤적이다. 카메라 추적은 별도 보간을 사용한다.
움직임 감소 설정에서는 점프와 카메라 전환을 즉시 처리한다.
유휴 상태에서는 animation frame을 예약하지 않는다. 비활성 탭에서는 렌더를 중단한다.

## 실행과 검증

루트에서 HTTP 서버를 사용한다. ES Module 때문에 새 홈을 file://로 열지는 않는다.

```
python -m http.server 8765 --bind 127.0.0.1
node --test scripts/test_home.mjs
python scripts/check_site.py
python scripts/build-travel.py --public-assets
python scripts/test_travel_route.py
node scripts/test_route_playback.js
node scripts/check_home_browser.mjs
```

브라우저 검사는 Node 24와 설치된 Chrome으로 확인했다. Chrome을 임시 프로필로 실행한다. 기본 주소는
`http://127.0.0.1:8765/`이며 `HYOJE_TEST_URL`, `HYOJE_CHROME`으로 변경할 수 있다.
서버는 별도 터미널에서 실행한다. 외부 사이트에는 연결하지 않는 로컬 전용 검사다.
스크린샷과 결과 JSON은 `Playground/verification/`에 저장하며 배포·커밋에서 제외한다.

2026-10-19 로컬 확인:

- 순수 로직 테스트 10개 통과: 정확한 8방향, 경계·장애물, BFS, 확대 월드,
  점프 입력 잠금·취소·다시 이동, 움직임 감소, 카메라 역투영·줌.
- Headless Chrome 브라우저 시나리오 19개 통과: 데스크톱, 320/360/390px 세로 및
  844×390 가로, 하단 시트 겹침, 평면 지도·키보드, 터치 점프·건물 선택·드래그·핀치,
  자동 이동·취소, 렌더 유휴화, Canvas 실패, 이전 북마크, 기존 체스 데이터 로딩.
- 기존 포트폴리오의 본문·작업물은 이전 HEAD와 비교하여 경로와 홈 링크 외 동일함을 확인.
- 공개 파일 패키징 결과의 로컬 참조 208개와 여섯 포트폴리오 카드 확인.
- 여행은 공개 스냅샷으로 재생성 후 기존 Python·JavaScript 회귀 검사 통과.
  이 과정에서 생성된 여행 HTML은 되돌렸다. 실제 배포에서는 CI가 최신 원고로 재생성한다.
- 실제 스마트폰, iOS Safari 실기기 검사는 하지 않았다. 모바일 결과는 Chrome 에뮬레이션이다.

## 배포와 다음 단계

기존 Pages workflow 하나를 유지한다. 여행 생성·회귀 검사 다음에 홈 로직·리소스 검사를
실행하고, allowlist만 `_site/`로 복사해 Pages artifact를 만든다.
공개 경로는 index.html, style.css, home/, portfolio/, assets/, works/, chess/, travel/뿐이다.
Playground/, data/, docs/, scripts/와 저장소 관리 파일은 artifact에 들어가지 않는다.
패키징은 비어 있는 출력 폴더를 요구하며 기존 파일을 삭제하거나 덮어쓰지 않는다.

V1에서 제외한 것은 실제 3D 회전·WebGL, 다른 체스 기물, 전투·게임 규칙,
방문자 저장 상태, 공개 lab 페이지, 거대한 월드다.
다음에는 실기기에서 조작감과 배터리 부담을 확인하고, 소품·장소를 데이터로 늘리거나
렌더러만 WebGL로 교체할 수 있다. 이동 규칙과 BFS는 그대로 재사용한다.
